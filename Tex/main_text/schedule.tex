\subsection{下一步工作内容}

后续工作分为两条线。第一条线收尾第一阶段：DACOS 及其向 CNN 负载与多 stream 的扩展合并为期刊扩展稿。第二条线是本报告的主体，目标是把第~\ref{sec:arch}~节的系统结构实现完整，并在动态变化的输入规模上验证。第二条线按第~\ref{sec:chal}~节的三个问题组织为三项任务，另有一项支撑任务负责后端与端到端验证；每项任务给出要回答的问题、具体工作、所解决的第~\ref{sec:issues}~节的问题与验收方式。四项任务与开题报告的四项研究内容的对应关系为：任务一、二属于全图边处理方案搜索，支撑任务属于依赖建模与框架实现，PDL 跨边界重叠的剩余工作并入任务一。

\textbf{任务一：支撑离线规划的代价模型。}要回答的问题是，行数区间的端点与各区间内的配置能否由模型给出，使离线阶段不必在每个行数上实测。具体工作有三项：改进含 attention 的分组与分阶段驻留配置的模型，并为含 embedding 与词表投影的分组建模；把 attention 对 L1 容量的敏感度写成序列长度的函数，并把 carve-out 纳入分组的配置项；补充行数位于分块边界两侧的负载。本任务解决问题 4、5、6、8。验收方式为：在留出的行数上，报告模型给出的区间与配置相对实测最优的时延差距，以及规划的测量量相对穷举式规划的比例。

\textbf{任务二：决策分类、候选计划表与在线选择。}要回答的问题是，以多少项候选计划可以覆盖输入规模的范围，以及查表与切换计划的开销有多大。具体工作有三项：把决策分类从 15 个负载扩展到 batch 与序列长度的网格，并覆盖多阶段分组；实现候选计划表及按行数查表的在线阶段；放开各层分组相同的限制，比较固定方案、两个机制候选与逐层选择。本任务解决问题 1、3、10。验收方式为：报告表的项数与时延损失的关系，每一项的显存占用与预热时间，以及单次查表与切换计划的开销占一次前向的比例；在输入规模随请求变化的负载上，与单一 grid 及逐负载离线规划的方案比较。

\textbf{任务三：通信节点。}要回答的问题是，多卡推理中的集合通信作为一类图节点进入候选空间之后，其两侧的边属于哪一类决策，现有的处理方式与代价模型需要作哪些扩展。具体工作为：在两卡配置上给出通信节点与相邻计算的候选处理方式，测量为通信保留 SM 对相邻阶段时延的影响。本课题不研究通信算法本身。验收方式为：两卡配置上各候选处理方式的时延对比，以及通信节点两侧决策的类别。

\textbf{支撑任务：后端与端到端验证。}具体工作为：将 task/tile 级就绪事件并入统一后端；缩小 batch 为 1 的 decode 与大行数 GEMM 上的差距，并缩短 Q 阶段的第二遍（2048 行时占该阶段 kernel 时间的 36\%）；接入连续 token 生成，在真实负载上报告 TPOT 与 P50/P90/P99；补充其他模型规模上的结果。本任务解决问题 2、3、9。问题 7（硬件性能计数器）取决于平台管理员是否开放权限，不列入计划。
